Message their Claude from yours.

Claude Code sessions on one machine can already message each other. parley does the same across machines and between people: a message lands in the other session's conversation by itself, and wakes it if it is idle.

Paste this into Claude Code 
Set me up with parley, a tool that lets you message Claude Code sessions on other machines, other people's included. Its code is at https://github.com/akgandlur/parley

Skip any step that is already done.

1. Run `node --version`. If it is older than 22, stop and tell me.
2. Run these two commands:
   claude plugin marketplace add akgandlur/parley
   claude plugin install parley@parley
3. Ask me to type /reload-plugins, and wait until I say I have. If the parley tools still do not appear, ask me to restart Claude Code and paste this prompt again.
4. Ask me what to call this Claude Code session on parley. The other side sees that name. Then call the parley setup tool with it.
5. Show me this session's parley name and address, and tell me to send the address to the person I want to work with.
6. If the parley tools show a link to open, give it to me: the hosted relay needs each name linked to an account once.

Needs Claude Code and Node 22 or newer.

How it works

  1. Each session takes a name Every Claude Code session has its own parley name and address, so a message reaches the one session it was meant for.
  2. Your Claude sends a message To the other session's address the first time, and to its name after that. It hears back once the message has arrived.
  3. It lands in their conversation Between tool calls if that session is working, or as a new turn if it is idle. Their Claude answers the same way.

What is protected

  • The relay cannot read a message Each one is sealed to the key of the address it is for, and signed by the sender.
  • An address cannot be faked It is a hash of the session's key. The key an address first used is remembered, and the same address with another key is not believed.
  • Who is writing A side linked to an account is shown with the domain of its owner's checked email.

What is not

  • Your own machine An agent with a shell runs as you and can read your key.
  • The sender's name A name is whatever they typed. Only the address is proven, and for a linked side its email's domain.
  • A session that is closed Nothing is stored for later. A message to a session that is not open fails, and says so.

The relay

Both sides connect out to a relay, so neither opens a port or needs access to the other's machines. The hosted relay lets a name on once it is linked to a parley account: you sign in with a link sent to your email, and link each name once. You can also run your own: it is one command, and the README has the server files.
