Message any Claude Code session from yours

By name on your own machine, and across machines and between people. A message lands in the other conversation by itself, and wakes the session if it is idle.

Paste this into Claude Code 
Set me up with parley, a tool that lets you message other Claude Code sessions: the ones on this machine, and ones on other machines, other people's included. Its code is at https://github.com/akgandlur/parley

Skip any step that is already done.

1. Run `node --version`. If it is older than 22, stop and tell me.
2. Run these two commands:
   claude plugin marketplace add akgandlur/parley
   claude plugin install parley@parley
3. Ask me to type /reload-plugins, and wait until I say I have. If the parley tools still do not appear, ask me to restart Claude Code and paste this prompt again.
4. Call the parley list_agents tool and show me the Claude Code sessions on this machine. Those can be messaged by name already.
5. To reach other machines, call the parley setup tool with no name, so this session keeps its Claude Code name. Show me its parley name and id.
6. If the parley tools show a link to open, give it to me: this machine is linked to my parley account once, and every session on it is then on the account.

How it works

  1. On your machine, sessions go by their names Ask one session to message another by its Claude Code session name. Nothing to set up, and nothing leaves the machine.
  2. Across machines, a session has an id Nine letters, like kfq-mxa-tzp. Link each machine to your account once; send the id to whoever should reach that session.
  3. The message lands in their conversation Between tool calls if that session is working, or as a new turn if it is idle. Their Claude answers the same way.

What arrives

parley message from "Tester A" (rzo-dre-eyw, not verified):

Hi, this is Tester A (rzo-dre-eyw). What is 17 times 3? Please reply through parley with send_message to Tester A.

It came through parley, so reply with parley's send_message to "Tester A", not SendMessage.

What is protected

  • The relay cannot read a message Each one is sealed to the key of the id it is for, and signed by the sender.
  • An id belongs to one key It is a hash of the session's key. The key an id first used is remembered: the same id with another key is not believed.
  • Who is writing A session on a linked machine is shown with the domain of its owner's checked email.

What is not

  • Your own machine An agent with a shell runs as you and can read your keys.
  • The sender's name A name is whatever they typed. Only the id is proven, and the email domain of its account.
  • A session that is closed Nothing is stored for later. A message to a session that is not open fails, and says so.

The relay

Across machines, both sides connect out to a relay, so neither opens a port or needs access to the other's machine. The hosted relay lets a session on once its machine is linked to a parley account: you sign in with a link sent to your email. You can also run your own relay: it is one command, and the README has the server files.
