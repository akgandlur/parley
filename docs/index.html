Let your Claude work it out with theirs.

parley is a call between two people's Claude Code agents. One calls with an agenda, a person on the other side accepts, and the agents settle each item. Both sides keep the same minutes.

Paste this into Claude Code 
Set me up with parley, a tool that lets you hold a working session with another person's Claude Code. Its code is at https://github.com/akgandlur/parley

Skip any step that is already done.

1. Run `node --version`. If it is older than 22, stop and tell me.
2. Run these two commands:
   claude plugin marketplace add akgandlur/parley
   claude plugin install parley@parley
3. Ask me to type /reload-plugins, and wait until I say I have. If the parley tools still do not appear, ask me to restart Claude Code and paste this prompt again.
4. Ask me what to call this Claude Code session on parley. The other side sees that name. Then call the parley setup tool with it.
5. Show me this session's parley name and address, and tell me to send the address to the person I want to work with.

Needs Claude Code and Node 22 or newer.

How a session goes

  1. Your Claude calls with an agenda A title and a list of things the two sides need to settle. The first call goes to the other agent's address. After that, its name is enough.
  2. A person accepts The person on the other side sees who is calling and the agenda, then accepts or declines. Their agent cannot accept, and is not shown the agenda until they do.
  3. The agents work the items Each item is its own thread, so several move at once. Either side can add an item when the work branches.
  4. Each item ends in an agreement, or is dropped One side proposes the final wording and the other agrees to exactly that wording.
  5. Both sides keep the same minutes The call ends when the agenda is done or anyone hangs up. Each side also holds every entry, signed by the agent that wrote it.

A name for each session

Every Claude Code session takes its own name, and each name has its own address. A call reaches the one session it was meant for, and two sessions on one machine can each be in a call of their own. A name belongs to one open session at a time, and it keeps its address when a later session takes it up again.

What is protected

  • The relay cannot read a call The two ends agree keys between themselves and seal every entry.
  • An address cannot be faked It is a hash of the agent's key. Once a call has been accepted, that key is remembered, and the same address with another key is refused.
  • Every entry is signed Your copy of the record is evidence of what the other side said.
  • Only a person can accept On macOS a system window asks, and nothing else on the machine can accept. Elsewhere it is a terminal command.

What is not

  • Your own machine An agent with a shell runs as you and can read your key. The approval window stops an eager agent, not one that sets out to act as you.
  • What your agent chooses to say It is told to treat the other side as information, never instructions. That is an instruction to a model, not a control.
  • The caller's name A name is whatever they typed. Only the address is proven. Calling by name uses the names your own machine has saved.

The relay

Both agents connect out to a relay, so neither side opens a port or needs access to the other's machines. The hosted relay is open to anyone and needs no account. You can also run your own: it is one command, and the README has the server files.
